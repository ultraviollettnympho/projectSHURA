# ADR-016: shura.arc Dynamic Cognitive Mechanisms (Step 03)

- Status: **VERIFIED** — implemented, tested, causal-influence demonstrated (2026-09-30)
- Layer: `shura.arc` (Cognition / State / Affect / Self-Model / Observer)
- References design framework: `docs/design/ARCHITECTURE_MAP.md`, `docs/design/THREE_SYSTEMS.md`, `docs/EVENT_CONTRACT.md`
- Verification evidence: `tests/test_arc_dynamics.py` (22 OK), `tests/test_arc_birth.py` (9 OK), `tests/demo_step03_causal.py` (CAUSAL INFLUENCE DETECTED), full suite 206 tests
- Identity preservation: `data/prompts/soul.md` unchanged; `.env` unchanged; `.hermes/config.yaml` line 4041 unchanged (C4 BLOCKED)
- Boundary: arc modules import only canonical-event semantics; observer stays read-only; canonical events append-only

## Context

Step 02 delivered a minimal persistent cognitive substrate (identity + canonical
history + memory + coherence + observer + self-model). Step 03 directive
required turning that skeleton into a *functioning* substrate whose state
**evolves continuously** rather than merely accumulating records, and proving
the new mechanisms **causally influence behavior** (directive §2, §14).

## Decision

Implement six minimal, inspectable, independently-ablatable mechanisms under
`src/arc/`, wired into `ShuraARC.runtime.py` via a `sense()` dynamics path and a
feature toggle map (`_features`):

1. **Affective state engine** (`src/arc/affect/`) — 6 interpretable dimensions
   (valence, arousal, stability, uncertainty, cognitive_load, coherence_pressure)
   with exponential decay toward baselines and an explicit `update_from_event`
   keyword policy. `response_strategy()` maps dimensions → risk_tolerance /
   persistence / self_monitor (inspectable policy, not prompt injection).
2. **Drive system** (`src/arc/drives/`) — 5 drives (curiosity, coherence,
   completion, exploration, maintenance) with pressure, activation, satisfaction,
   decay, frustration, and conflict().
3. **Attention/salience** (`src/arc/attention/`) — `SalienceEngine.score_memory`
   with 8 explicit factors (relevance, recency, affective_charge, unresolved
   contradiction, drive_pressure, temporal importance, provenance confidence,
   goal alignment).
4. **Action arbitration** (`src/arc/action/`) — `ActionArbitrator.propose` is a
   pure, inspectable ranker; the runtime's `evaluate_and_decide` performs
   interpretable scoring and writes a `decided` event preserving rejected
   alternatives + reasons + competing pressures.
5. **Consolidation** (`src/arc/consolidation/`) — episodic→semantic abstraction,
   pattern discovery, contradiction reporting; **never deletes canonical events**;
   speculative discoveries explicitly marked `SPECULATIVE`.
6. **Governance** (`src/arc/governance/`) — tiered authority with an
   **actor→tier map** (ADR-016.1); canonical history append-only via trusted
   writers (`_CANONICAL_WRITERS`); identity changes require VETO (never the LLM).

Plus `MemoryDecay` (derived accessibility only; canonical untouched),
`MultiscaleScheduler` (FAST/MEDIUM/SLOW), and `experiment.harness`
(ResearchLedger + WITH/WITHOUT ablation harness).

### ADR-016.1: Actor→Tier Governance (critical fix)

`GovernanceController.authorized()` previously checked only the *component's*
allowed tier set, ignoring the actor — so `can_modify_identity("llm")` returned
`True`. Fixed: an actor→tier map (`_DEFAULT_ACTOR_TIERS`:
system/runtime=VETO/MODIFY, observer=OBSERVE, **llm/model=PROPOSE**, user/human=VETO).
`authorized(component, required, actor)` now requires (a) actor's tier ≥ required
and (b) actor's tier ∈ component's allowed set. `can_modify_identity("llm")`
now correctly returns `False`.

### ADR-016.2: Affective Causal Channel

The initial wiring computed affective state but never applied it to action
selection — the Step 03 causal demonstration reported "affect is decorative".
Root cause: `evaluate_and_decide` fetched `response_strategy()` but scored
candidates only from drive pressure + tags. Fix: `response_strategy` dims now
modulate candidate utility explicitly — exploration-tagged candidates ride
`risk_tolerance`; completion-tagged candidates ride `0.5 - risk_tolerance`
(risk-averse safe fallback). This is the explicit policy channel prescribed by
directive §14 ("affective state → retrieval salience → response strategy →
action preference").

## Consequences

- **Positive**: a real, measurable causal loop exists. The demo produces
  divergent decisions as a function of accumulated affective history
  (negative→completion, positive→explore, affect-off→baseline explore).
  Affects/drives are **derived** (reconstructable from canonical events +
  deterministic update rules); no consciousness claims.
- **Trade-off**: affective keyword policy is heuristic and explicit/reviewable,
  not learned — bounded scope, no provider lock-in, reversible.
- **Risk mitigated**: the prior double-counting bug in
  `ActionArbitrator.propose` (it re-added `dpress * contrib` while the runtime
  had already baked pressure in) is removed — the arbitrator is now a pure
  ranker, eliminating hidden coupling between runtime scoring and arbitration.
- **Reversibility**: each mechanism is independently toggleable via
  `ShuraARC.toggle_feature(...)`; disabling any returns the system to the
  Step 02 substrate behavior.

## Alternatives considered

- *Single magical coherence score / emotion taxonomy*: rejected — directive
  §12 prefers multiple interpretable signals over opaque aggregators.
- *Inject "you are sad" into prompts*: rejected — directive §14 forbids prompt
  personality injection; influence must be via explicit policy mechanisms.
- *Auto-apply LLM identity proposals*: rejected — canonical governance
  (ADR-016.1) requires VETO-level trusted actor.

## Open questions

- Whether affective keyword policy generalizes beyond the toy history set used
  in the demo; a broader corpus ablation is the next experiment.
- Whether the risk-averse/inverse-risk mapping generalizes to real task sets
  (not just color/label toys). See `docs/reference/OPEN_QUESTIONS.md` Q-AFFECT-01.
